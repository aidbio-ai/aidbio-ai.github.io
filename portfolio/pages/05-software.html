Chapter 05 · Software

A one-off analysis answers one experiment. Software answers a class of them.

Every chapter so far ends in a bespoke analysis built for one paper. The software step asks a different question: what if the same reasoning — mechanism, network, data, prediction — could be packaged so the next dataset does not require starting from zero?

From analyses to reusable tools

AidBio's current open-source workflows

AidWeather

A Python library and CLI that turns NASA POWER weather and solar-radiation data into clean, cached, analysis-ready tables — for a single point, a transect, or a whole region.

Explore AidWeather → · GitHub ↗

AidGSEA

A modular workflow that takes public transcriptomic studies — processed GEO matrices or raw SRA reads — through preprocessing, dimensionality reduction, and Gene Set Enrichment Analysis, while keeping exploratory gene ranking clearly separate from publication-grade differential-expression inference.

See on AidBio.com →

Aid2GO

A graph-learning workflow for protein-function prediction that links proteins, protein-protein interactions, the Gene Ontology hierarchy, and experimentally supported GO annotations into one heterogeneous graph, using GraphSAGE and GAT variants over ProtBERT sequence embeddings.

See on AidBio.com →

AidFarm

An artifact-driven agronomic workflow: schema-confirmed ingestion, deterministic ETL, statistics and figures, and evidence bundles with a claim ledger — so LLM-assisted reporting through LangGraph and local Ollama models reasons over file-backed evidence instead of raw, unverified files.

See on AidBio.com →

AidViz

A visualization-only toolkit that intentionally does not fetch data or train models: static publication figures, interactive dashboards, and climate storytelling plots built from clean DataFrames, keeping data provenance and presentation responsibilities cleanly separated.

See on AidBio.com →

The pattern across all five

Separation of concerns, carried over from the lab notebook

Each tool deliberately keeps one responsibility narrow: AidWeather only assembles clean climate data; AidViz only renders it; AidFarm only builds evidence bundles; AidGSEA only separates exploration from publication-grade inference; Aid2GO only predicts graph edges with an explicit confidence signal.

That discipline is the same one from the mechanism chapter — distinguish measured result from interpretation from inference — just expressed as software architecture instead of a lab protocol.

Software is a mechanism paper you can run on next year's dataset.

Which leaves one last step: what does it mean to put all six of these — mechanism, networks, data, models, software — under one operating name?
